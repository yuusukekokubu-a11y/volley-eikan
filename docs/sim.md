# 試合計算（1ラリー）メモ

`src/sim/` が試合の計算。描画は知らない。`simulateRally(input)` が1ラリーの記録 `RallyRecord` を返す。

- 型：`src/sim/types.ts`
- 調整用の数値：`src/sim/constants.ts`（試作で変える前提の値はすべてここ）
- 特能の受け皿：`src/sim/traits.ts`（今はサーブの解禁型2つだけ登録）
- 確認用：`npm run rally`（多数のラリーの集計）、`npm run rally -- 19`（種19のラリーの中身）、`npm run tactics`（能力が偏ったチームでの作戦の比較）

## 記録の形

- 座標はメートル。x は長辺方向でネットが x=0、チームAは x<0、Bは x>0。y は短辺方向、z は高さ
- `placements`：ラリー開始時の選手の位置
- `events`：時刻順。`move`（移動）、`jump`（跳ぶ）、`action`（サーブ・レシーブ・トス・スパイクなどの動作）、`land`（ボールが床に落ちた）、`point`（得点）
- `ball`：ボールの軌道の区間の列。水平は等速、高さは `z0 + (z1-z0)s + 4·bulge·s(1-s)`
- スパイクの `action` には打点（cm）、ブロックの到達点（cm）、ブロッカー、ブロックの上から打ち抜いたか、が入る
- レシーブ・ディグの `action` には「位置のずれ（m）」と「回転・勢い（0〜1）」が入る
- `load`：選手ごとの負荷（跳んだ回数・動いた距離など）。疲れへの換算は試合側（次の段階）で行う

## 仕様にない部分で決めたこと（現実のバレーに合わせた）

- 能力：身長は cm、ほかは 0〜100。ポジション適性も 0〜100
- 打点＝身長×1.33（指高）＋跳躍から決まる跳び上がり（45〜100cm）。ブロックの到達点は跳び上がりの78%
- ネットの高さ：高校男子2.40m、高校女子2.20m
- 並びは 5-1 を想定。リベロは後衛のミドルと自動で入れ替わる（サーブを打つミドルは除く）
- サーブレシーブはリベロとアウトサイドを中心に3人。セッターは受けない
- トスの種類：速攻・時間差・平行・オープン。ずれが小さい時だけ速いトスを使える。セッターが1本目を触った時や、ずれが大きい時は、ほかの選手が二段トス（オープンのみ）
- 打てないトスはつなぎで返す（相手のチャンスボール）。ずれが大きすぎるレシーブは相手コートへ返ってしまうことがある
- スパイクの結果：ミス（ネット・アウト）／フェイント・軟打／ブロックのシャット・ブロックアウト・ワンタッチ／抜けた強打
- ブロックは「反応→横移動→踏み切り」がトスの滞空時間に間に合うかで枚数と間に合い具合が決まる。時間差ではミドルがフェイクに跳ぶことがある
- 守備は「ボールが来るまでに走れる距離＋飛びつき」で届くかを判定。跳んだ選手は着地してすぐは動けない
- シャットされたボールを味方が拾う（フォロー）ことがある
- 打ち分け：テクニックが高いほど守備のいない所を選べ、狙いのずれも小さい。低い打点だとネットを越えるために深くしか打てない
- 男女の重み：体の能力（跳躍・パワー・スピード）が攻撃力・サーブの威力に効く量に「体の重み」、テクニックに「技の重み」、作戦が合った時の補正に「作戦の重み」を掛ける。ブロック能力（読みとタイミング）と、移動の速さそのものには掛けない
- サーブ：フローターは誰でも打てる。ジャンフロ・スパイクサーブは解禁特能が必要（両方あればスパイクサーブ）
- ダイレクト：相手の返球がネットから1.5m以内に来たら、届く前衛が直接打つ（基本の動作）。場面 `direct` で特能が効く

## 記録の書き方（結果には影響しない）

- レシーブ・ディグ・フォローの移動先は「体の立ち位置」。触る点（動作の位置）から、ボールが進んでくる向きの先へ腕の長さ分（飛びつきは長め）ずらす。コートの外・ネットの向こうにはしない。届くかどうかなどの計算は触る点で行う
- ボールに関わる選手（受ける・トス・ブロック・フォロー）は、読む時間（能力で決まる）の後すぐ全力で動き出し、間に合えば先に着く。間に合わない時は触る時刻まで走り続ける
- スパイクの助走は、踏み切りの時刻に着く決まった長さの移動として記録する
- 新しく決まった移動は、それより後に始まる予定だった同じ選手の移動を取り消す
- 記録の見た目の修正で結果が変わらないことは `tests/outcome.test.ts`（保存してある結果との照合）で確かめる。結果そのものを変える修正をした時は `npx tsx scripts/outcome-fixture.ts > tests/fixtures/outcomes.json` で作り直す

## 判断

判断を表す能力はなく、既存の能力で正確さが決まる。

- サーブの狙い：テクニック（場面 `serveAim`）が高いほど多くの候補を比べ、レシーバーが取りにくい所を選ぶ。狙いどおり打てるかもテクニック
- 配球：セッターのテクニック（場面 `setChoice`）が高いほど、相手ブロックが薄くなりそうな攻撃を選ぶ
- ブロックの読み：ブロック能力（場面 `blockRead`）で、トスを見て動き出すまでの時間と、時間差のフェイクに跳ばされる確率が決まる
- スパイクの打ち分け：テクニックが高いほど守備のいない所を選べ、狙いのずれも小さい。ブロックの手に当てずに打て、当たってもずらして当てて止められにくい
- 軟打への切り替え：ブロックの壁が厚いのを読めるほど（テクニック）軟打でかわす
- レシーブの動き出し：打球を読んで動き出すまでの時間はテクニック、走る速さはスピードで決まる

女子はテクニックの重みが大きい（1.35）ので、軟打や打ち分けでブロックを避け、強打が減った分レシーブで拾われてラリーが続く。目安（同程度のチーム同士）：ブロック得点 男子11%・女子10%、平均打数 男子6.4・女子7.6

## 特能の受け皿（spec.md「特能の数値と型」）

- `stat`（青・赤・金）：`{ 場面, 能力, 段階 }` の組を持つ。段階は ±1/3/5/10/15 だけ（`validateTrait` で確認）。計算は判定のたびに場面の一覧を作り、その場面での能力を引く。確率や距離を直接いじる口はない
- `target` に `frontRow` / `backRow` を指定すると、持ち主と同じ列の味方にも効く（号令・守備の要用）
- `unlock`（解禁型）：ジャンフロ◯・スパイクサーブ◯・バックアタック・ブロード・ツーアタック。今の計算で動作があるのはサーブの2つだけで、ほかの3つは特能の実装時に動作を入れる
- `style`（緑）：軸と値だけを持つ（例：サーブの狙い方＝人狙い／つなぎ目狙い）。計算への反映は特能の実装時
- 打点・ブロック到達点は特能の影響を受けない（身長と跳躍だけ）
- 場面の一覧と、今の計算で実際に使っている場面は `traits.ts` の `Scene` に書いてある
